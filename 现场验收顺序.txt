Windows EXE 必须真实验收
1. build.bat 完成并自动打开最终目录后，确认 delivery\26\26.exe、README、exam_id.txt、data 和清洗审计文件。
2. 关闭 Python 服务，确认其控制台已退出；双击 delivery 内的 EXE，不选择 build\artifacts 中间产物。
3. 服务自动开浏览器或控制台显示本机地址；确认实际进程是 26.exe，而非原 Python 服务。
4. 登录 admin，逐项检查台账、图表图片、清洗下载、序号、用户GET/POST权限。
5. EXE 中创建 winjudge / Judge@123，关闭 EXE 后重启，确认账号仍可登录。
6. 检查数据库在 EXE旁 runtime\、新 CSV 和图在 EXE旁 output\，没有写入临时解包路径。
7. 安装完依赖/打包后断网，刷新并操作页面，确认CSS/图表可用；EXE应无需Python运行。
8. 如有另一台不装Python的同架构Windows环境，将整个交付目录放到可写目录再验证。
   如没有这种环境，不要声称已在无Python环境实测。不要在考试机上为测试而卸载Python或重启还原系统。
9. 可执行下面命令再做源码自动验收（需要Python，只用于测试，不是EXE运行依赖）：
   .venv\Scripts\python.exe -m unittest discover -s tests -v
10. 最终提交26目录与26.zip，附26_源码.zip及说明。

当前交付已在 Linux 使用真实 CSV 进行自动测试；Windows 打包、桌面双击、浏览器人工操作和无 Python 运行待本机验收。
